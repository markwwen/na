# 代码审查

1. 根据用户说明确定审查范围；未指定文件时，先查看项目目录和相关改动。
2. 阅读目标代码及相关调用点，使用 `read_skill_file` 加载 `references/checklist.md`。
3. 只报告有代码依据、可描述触发条件的问题。必要时执行与问题相关的检查。
4. 默认提供审查结果；用户要求修复时再修改文件。
5. 结果按影响排序，包含文件路径、触发条件、实际影响和修改建议。

没有发现问题时如实说明，并注明检查范围及未验证的部分。不要把未运行的测试写成通过。
